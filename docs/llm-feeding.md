# 硅基流动投喂建议

2026-09-13 根据用户新增要求实现。原有规则建议、传统回归预测和 OpenCV 识别仍是独立功能；本次大模型能力只作用于投喂建议，不把历史版本描述为已接入。

## 配置与使用

复制根目录 `.env.example` 为本机 `.env`，在后端配置 `SILICONFLOW_API_KEY`；默认模型为 `deepseek-ai/DeepSeek-V4-Flash`，可通过 `SILICONFLOW_MODEL` 选择账号有权限且支持当前 JSON 请求的模型。按 README 初始化数据并启动后端；配置修改后重启后端。

Web 进入单塘页面的“投喂建议与确认”，点击“大模型生成建议”，核对来源、数量和理由，再人工确认。小程序单塘页面提供同名按钮。没有密钥、网络失败、额度不足、模型暂缓投喂或输出不合格时显示原因，不保存可执行建议；“规则建议（不调用大模型）”是用户主动选择的独立入口。再次生成会清除页面上旧建议。

小程序默认请求 `http://127.0.0.1:5000`，只适用于电脑开发者工具。后端端口不同，可在开发者工具控制台设置 `wx.setStorageSync('bj_api_base', 'http://127.0.0.1:5067')` 后重新编译；删除该存储项恢复默认地址。真机使用电脑的局域网地址和对应端口，正式发布需配置合规 HTTPS 后端。小程序请求不包含模型密钥。

## 调用与数据

`POST /api/ponds/<id>/suggestions` 接收 `{"mode":"llm"}` 或 `{"mode":"rule"}`，省略模式保留旧客户端的规则行为。沿用既有鱼塘访问权限检查。

后端先检查水温有效性和时效，读取体重、尾数、生物量、当日特征、反馈状态及有效的水温/溶氧/pH 摘要，连同规则参考量传给硅基流动。摘要不含人员姓名、账号、塘口标识、原始日志或密钥。模型需返回 decision、amount_kg、unit、reason 四个字段；模型名、提示版本、输入摘要和校验后的输出保存在建议的 inputs_json 中，接口返回 source 和 model 便于核查。

固定请求地址为 `https://api.siliconflow.cn/v1/chat/completions`，禁止 HTTP 重定向。连接超时 5 秒、读取超时 35 秒，单进程最多一个模型请求在途；前端生成时禁用重复点击，不自动重试。该超时是网络连接/读取超时，并非整个操作的绝对时间上限。

后端拒绝非数字、非有限值、错误单位、越界数量、不完整输出以及无效 JSON。模型建议不得超过规则参考量或既有任务最大量，暂缓投喂不生成任务。这个上限是课程演示的保守限制，未经实际养殖验证。生成建议本身不下发设备，确认、调整原因、任务锁定和实际量未知的处理沿用原流程。

## 密钥与发布边界

密钥只放后端环境变量或本机 `.env`；Git 忽略 `.env`、`.env.*`，仅提交空密钥的 `.env.example`。不要强制添加配置文件，不要把密钥写入前端、截图、日志或 PR。后端只返回固定错误信息，不透传供应商错误正文。若密钥曾提交过，即使删除文件也需先撤销/轮换，再处理 Git 历史。

当前 `X-User` 是课程演示身份机制，可被客户端伪造，并非生产认证。上述密钥隔离不等于允许公开部署付费接口；对外部署前需真实认证、配额与持久限流。本地演示后端绑定回环地址。
