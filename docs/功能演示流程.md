# 功能演示流程 · 白蕉水产养殖管理平台

本文档用于答辩演示与功能验收。每一步都经过实测，未实测的会明确标注。

---

## 一、准备（演示前 5 分钟）

```bash
cd 白蕉水产养殖管理平台
python scripts/seed_demo.py     # 恢复演示数据（幂等，可反复运行）
python backend/app.py           # 启动后端
```

浏览器打开 <http://127.0.0.1:5000>

**演示前确认**：
- 右上角「终端仿真」开关状态与你要演示的环节一致（见第三部分）
- 用户切到「李塘主（塘主）」——全权，能看到全部鱼塘

**演示数据被弄乱了怎么办**：重跑 `python scripts/seed_demo.py` 一键恢复。

> ⚠️ **不要**在演示前跑 `tests/test_acceptance.py`。它默认用独立临时库、
> 不会动演示库，但若加了 `--base` 参数会清空演示数据。

## 三、完整演示流程（约 8 分钟）

### 第 0 步 · 开场：总览（30 秒）

**打开首页。**

讲：「两个鱼塘的水温溶氧实时可见，仪表盘显示是否在安全区；下方是今日各塘投喂量和异常分布。在线用户与终端连接数分开统计。」

> 注意 A02 只有环境曲线、没有投喂记录——这是**刻意的**：课堂 CSV 只有 A01 的真实数据，
> A02 用于演示多塘比较，不伪造投喂量。

---

### 第 1 步 · 正常闭环（2 分钟）—— **开关置「开」**

1. **右上角「终端仿真」开关 → 确认显示绿色「运行中」**（若显示「已关闭」点一下打开）
2. 进入 **A01 号塘**
3. 点 **「生成投喂建议」**
4. 看建议卡片：建议量、规则版本、**完整依据**（鱼重 × 尾数 × 温度系数 × 摄食系数）
5. 把确认量改小一点，**修改原因填「现场观察抢食较弱」**，点「确认并下发」
6. **观察下方「投喂任务记录」**：约 3 秒内状态从「已下发待回执」→「已完成」
7. 点该任务 **「详情」**：看到建议量 / 确认量 / 实际量（标 `simulated`）、三条回执

讲：「**建议量、确认量、实际量三者分开保存**——这是需求书反复强调的。改量必须填原因，这是留痕。仿真终端回执的实际量标为 `simulated` 而不是实测，因为程序没真的投料——**不把估算伪装成实测**。」

---

### 第 2 步 · 异常闭环（2 分钟）—— **开关置「关」**

1. **把开关关掉**（点一下，变黑）
2. 回 A01，再点「生成投喂建议」→「确认并下发」
3. **观察任务表**：状态停在「已下发待回执」，**且表格右上角出现「1 个任务占用设备」**
4. 此时**再下发一次** → 被拒绝：「设备已有未结束任务…」
5. **无需操作**，等约 10 秒 → 状态自动变「结果未知（待核查）」
6. 去 **「待核查」页** → 看到该任务（默认筛选「占用设备」）
7. 点 **「核查」** → 结论选「未执行」→ 填写核查依据 → 填设备恢复依据 → **勾选三项确认** → 保存
8. 回 A01，「占用设备」提示消失，可以正常下发了

讲：「设备失联时系统**不会盲目重发**——先标记结果未知、保留设备占用，等人工核实。核查还要勾选三项现场确认（终端无任务、旧指令不会执行、设备可用），**这是管理员的现场核实记录，不是系统自动证明安全**。」

> 若时间紧：把 `task_timeout_sec` 调成 3 秒再演示，更快。

---

### 第 3 步 · AI 预测（1 分钟）

A01 页 → **「AI 模型预测」** → 依次点「生长预测」「投喂量预测」「水质预测」

讲：「生长预测基于历史称重做线性回归，当前 780.8g、日增 2.6g、约 8 天达标，R²=0.997。**数据不足时明确拒绝，不返回伪预测**——比如 A02 称重不够就提示无法计算。」

---

### 第 4 步 · 视觉识别（1 分钟）

A01 页 → 「塘口监控」→ **「上传图片识别」** 选一张水下照片

讲：「OpenCV 做水面亮残差 + 连通域检测，检出后生成**待确认事件**——算法只能说『我怀疑』，结论必须人来下。**这是启发式算法不是深度模型**，反光水草可能误报。」

> OCR 按钮需本机装 tesseract-ocr；未装时会明确提示依赖缺失，不做假识别。

---

### 第 5 步 · 多塘比较与排行榜（1 分钟）

**「多塘比较」页** → 看投喂量、水温、溶氧、告警次数四组对比图 + 饲料系数

讲：「A01 饲料系数 1.29，含义是 1.29 公斤饲料长 1 公斤鱼，落在真实鲈鱼范围（1.2~1.8）。**A02 明确标『不参与排名』**——称重数据不足，不凑名次。」

**「交流·排行」页** → 发一条帖子，看排行榜

---

### 第 6 步 · 权限与移动端（1 分钟）

1. 右上角切到 **「王师傅（运营者）」** → 只看得到 A01；打开 A02 会被拒绝
2. 切到 **「刘师傅」** → 只看得到 A02
3. **F12 切手机视口（390px）** → 页面无横向滚动

讲：「**权限在后端校验**，不是前端藏按钮——直接调接口同样会被拒（403）。」

---

### 第 7 步 · 收尾（30 秒）

**「异常」页** → 告警列表、审计日志、系统配置

讲：「所有控制操作留痕：谁、何时、做了什么。采样周期、有效期、量程、超时阈值都统一配置、改动可追溯。」

## 五、演示保险措施

| 风险 | 应对 |
|---|---|
| 数据被弄乱 | `python scripts/seed_demo.py` 恢复（幂等） |
| 开关状态不对 | 看右上角开关颜色；绿=开，黑=关。状态每次点击都会与后端同步 |
| 设备被占用发不出任务 | 待核查页默认列出所有占用任务，核查即可释放 |
| 网络中断 | 前端零外部依赖，离线可演示 |
| 超时等太久 | 演示前把 `task_timeout_sec` 调成 3~5 秒 |
