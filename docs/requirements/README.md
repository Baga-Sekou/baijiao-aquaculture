## 阅读重点

- 需求第 2.3 节明确本期方案与扩展范围；第 10 章列出仍需评审的实施条件。
- 投喂采用“系统建议、人工确认后执行”，建议量、确认量和实际量分别保存。
- 执行结果未知时不自动重发；人工核查并满足设备恢复条件后，才解除占用。
- 疑似死鱼需要人工确认；模拟数据、规则或模型拟合不能证明真实节料、疾病改善或经营收益。
- 时序图表达设计职责和消息关系，不表示当前已经接入真实硬件。

## 文档与实现的关系

本目录是设计依据。仓库根目录 README 描述实现与使用方式，测试记录说明各次检查的范围；三者应分别阅读。遇到不一致时，应逐项核对并经小组决定调整需求或实现，不能只依据本文档宣称功能已完成。

文中引用的课件、课堂照片、录音和模拟数据用于追溯课程依据，原始资料没有随本次文档提交上传。

## 后续维护

需求变更优先在 Markdown 正文中讨论和记录，并同步更新 Word。涉及参与模块、任务状态、消息或异常恢复时，同时更新配套时序图。每次变更说明版本、原因和评审结果；不要将旧版 Word 与新版正文混作同一交付版本。
